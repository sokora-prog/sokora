## 2. FLUX D'AUTHENTIFICATION (TOUS MODULES)

### Flux standard — 3 étapes
```
1. Saisie numéro de téléphone
   └─ POST /auth/request-otp → debug_code (dev) / WhatsApp (prod)

2. Saisie code OTP 6 chiffres
   └─ POST /auth/verify-otp-login
       ├─ Compte existant avec MDP → JWT token → Accès direct
       └─ Nouveau compte / sans MDP → Étape 3

3. Création mot de passe (première connexion uniquement)
   └─ POST /auth/verify-otp-login (avec password)
       └─ Compte créé + JWT token → Accès
```

### En production (VPS)
- Le `debug_code` est **supprimé** des réponses API
- L'OTP est envoyé par **WhatsApp Business** ou **SMS** (intégration à câbler : Twilio / Orange CI)
- Configurer dans `backend/.env` : `SMS_GATEWAY_URL`, `SMS_API_KEY`

## 4. ARCHITECTURE TECHNIQUE

### Backend FastAPI
```
/auth/request-otp          POST  Génère OTP 6 chiffres (en mémoire, 10 min)
/auth/verify-otp-login     POST  Vérifie OTP + crée/authentifie compte
/auth/login                POST  Connexion directe téléphone + mot de passe
/auth/me                   GET   Utilisateur courant (JWT)
/auth/register             POST  Inscription gérant (legacy)
/client/auth/request-otp   POST  OTP client mobile
/client/auth/verify-otp    POST  Vérifie OTP client
```

### Sécurité production (à appliquer avant go-live)
- [ ] Changer `SECRET_KEY` dans `backend/.env` (valeur aléatoire 64 chars)
- [ ] Supprimer `debug_code` des réponses OTP en production (`ENV=production`)
- [ ] Activer HTTPS (Let's Encrypt via Certbot)
- [ ] Configurer passerelle SMS/WhatsApp pour envoi OTP réel
- [ ] Mettre en place rate limiting sur `/auth/request-otp` (5 req/min/IP)

## 7. AUDIT — PROBLÈMES RÉSOLUS

| # | Problème | Solution appliquée |
|---|----------|--------------------|
| 1 | Tous les modules utilisaient la même page de connexion démo unifiée | Pages de connexion distinctes par module avec branding et messages métier différents |
| 2 | Auth par mot de passe seul (pas d'OTP) | Flux OTP 3 étapes implémenté dans tous les modules |
| 3 | Comptes démo hardcodés visibles en prod | Mode démo conditionnel (debug uniquement) |
| 4 | Conflit de port DOMO vs Hôtel (5173) | DOMO déplacé sur 5178 |
| 5 | `allowedHosts` Vite bloquait les tunnels Cloudflare | `allowedHosts: true` ajouté à tous les vite.config |
| 6 | KYRION sans authentification | Login page OTP + protection des routes ajoutée |
| 7 | SECRET_KEY par défaut dans le backend | Avertissement actif + doc pour changer en prod |
| 8 | Graphes en bougies manquants dans KYRION | lightweight-charts installé, PairDetail créé avec OHLC |
| 9 | Rôles DOMO non différenciés (tous → admin) | Routage par rôle : admin/agent/resident → vues distinctes |
